# 旅迹 Travel Footprint 课程设计优化说明

## 一、基线分析

20260819 基线已经具备 Spring Boot、Thymeleaf、JPA、权限控制、高德地图、图片与视频上传、PWA、小程序和 Android 客户端，功能完整度较高。本轮不做大规模技术栈迁移，重点解决课程设计中容易被追问的性能、安全和工程质量问题。

| 方向 | 基线问题 | 优化方案 | 可展示效果 |
| --- | --- | --- | --- |
| 视频播放 | 每次请求返回整个视频，拖动进度条和弱网播放体验较差 | 支持 HTTP Range、206/416、`Accept-Ranges`；文件系统按片段读取 | 浏览器可按需加载、拖动定位，降低单次内存与流量 |
| 视频上传 | 已有格式和大小校验，但预览信息较少 | 上传前展示文件大小、时长、分辨率 | 用户能在提交前确认素材是否正确 |
| 数据查询 | 护照页逐篇统计照片；计划页逐计划汇总消费 | JPQL `group by` 批量聚合 | 查询次数由随数据量增长改为固定批次 |
| 离线缓存 | Service Worker 会缓存首页、地图等服务端 HTML | 仅缓存静态资源和中性离线页，页面导航走网络 | 避免同一浏览器切换账号后复用旧用户页面 |
| 容器稳定性 | 72 MB 堆内存对图片/视频请求偏紧 | 256 MB 容器内将 JVM 堆上限调整为 128 MB | 保留系统空间的同时减少大文件处理 OOM 风险 |

## 二、关键实现

### 1. 高德地图

- 地图使用高德 JS API 2.0，并通过环境变量读取 Key 与安全密钥。
- `/map` 单独使用允许高德域名的 CSP，其他页面保持更严格的默认策略。
- 支持地点聚合、私人足迹路线、时间轴播放、全屏浏览和高德导航跳转。
- Key 和安全密钥不写死在源代码中，继续使用 `.env` 或部署环境变量。

### 2. 视频上传与播放

- 服务端检查文件大小、MIME 声明和 MP4/WebM 文件头，不能仅靠扩展名绕过。
- 视频沿用足迹的公开、关注者、私密、用户启用和审核状态权限。
- 浏览器发送 `Range: bytes=start-end` 时返回 `206 Partial Content`、准确的 `Content-Range` 和片段长度。
- 越界或不支持的多段范围返回 `416 Requested Range Not Satisfiable`。
- 未授权请求在读取文件内容之前即被拒绝，减少无效 I/O。

### 3. 查询性能

- 旅行护照通过一次分组查询获得所有足迹的相册数量。
- 行程计划通过一次分组查询获得所有计划的消费总额。
- 网页端与小程序端共用批量相册统计；小程序用户资料使用数据库 `count`，不再为统计数量加载完整足迹列表。
- 这两处是典型 N+1 查询案例，适合在答辩中解释“数据量增大后为何会变慢”。

## 三、验证结果

- JavaScript 语法检查：通过（帖子编辑器、Service Worker、高德地图脚本）。
- Maven 完整测试：60 项通过，0 失败，0 错误。
- 测试覆盖视频格式校验、文件分片读取、访问权限、206 响应、416 响应、地图 CSP 和主要 Web 流程。

## 四、答辩演示建议

1. 登录后创建一条私密足迹，选择 MP4 或 WebM，展示上传前的大小、时长和分辨率。
2. 打开详情页播放视频并拖动进度条，在浏览器网络面板展示 `Range` 请求和 `206` 响应。
3. 未登录访问同一视频地址，展示 404 隐藏资源存在性。
4. 打开个人高德地图，播放旅行时间轴，再点击导航入口。
5. 结合聚合查询代码说明 N+1 问题及优化前后的查询次数变化。

## 五、用户体验增强（第二轮）

- 发布和编辑足迹时显示真实上传百分比、保存阶段状态与失败重试入口；上传期间关闭页面会收到提醒。
- 视频播放器自动使用足迹相册封面作为 `poster`，进入详情页时仅预加载元数据，避免未播放就传输完整视频。
- 高德配置有效时，目的地输入会搜索真实 POI；选择结果可自动填写地点、省份和经纬度，也可以点击地图或拖动标记修正位置。
- 高德不可用时继续保留项目内置地点建议，保证断网演示和课程答辩不被第三方服务阻断。
- 首页使用 JPA Specification 完成公开状态、关键词、分类、地点、关注范围和内容来源筛选，并通过数据库稳定分页，每页只加载 6 条足迹。
